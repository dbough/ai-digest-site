Google open-sources AQuA to diagnose failures in production AI agents

First reported 2026-11-13

Google released AQuA (Ambient Quality Agent), an open-source reference implementation that analyzes production agent sessions, identifies recurring failure patterns, and investigates root causes against deployed source snapshots. In a 32-session replay reported by InfoQ, developers cut seat-selection bypasses from 15 sessions to two and dietary-preference omissions from seven to zero after prompt changes. These are Google-reported results from a replay, not a broad production study.

Why it mattersObservability for agent failures is a major gap as agents move into production, and an open reference implementation gives teams a concrete pattern to copy.
For buildersConsider adapting the session-analysis approach to log review and regression detection in your own agent deployments.

Pros

  • Open source, so teams can inspect and adapt the approach
  • Demonstrated the ability to find and fix recurring failure patterns

Cons

  • Evidence comes from a small 32-session replay
  • Reference implementation may need significant adaptation for other stacks

Stanford's Memorilla gives frozen LLMs a compact learned memory

First reported 2026-11-14

Stanford researchers released Memorilla, an open-source 194M-parameter memory module that reads a document collection and hands a frozen LLM just 16 memory tokens. Reported results on FactKG show a frozen Qwen3-8B scoring 84.33% with Memorilla versus 80.43% with all documents in context, using 108x fewer document tokens. Code, training recipes, and checkpoints are released under Apache 2.0. These numbers come from the release coverage and have not been independently replicated here.

Why it mattersIf compact memory modules hold up, they offer a cheaper way to give models access to large document sets than stuffing everything into context.
For buildersTest whether a memory-token approach can replace long-context retrieval for your document-heavy workloads, after checking results on your own data.

Pros

  • Large token savings if the results generalize
  • Open code, training recipes, and checkpoints under Apache 2.0

Cons

  • Results are reported on one benchmark and need replication
  • Requires training a memory module per document collection, which adds engineering overhead

AWS shows how to route coding agent requests across models on Bedrock with NVIDIA NeMo Switchyard

First reported 2026-11-13

AWS published a guide on routing coding-agent traffic to the right model on Amazon Bedrock using NVIDIA NeMo Switchyard. The post argues that per-token price is a poor cost signal for agents, because total task cost depends on turns, replayed history, and retries. Routing decisions should therefore be based on whole-task cost and completion rates.

Why it mattersMeasuring cost per completed task rather than per token is a more accurate way to manage agent economics, and routing is becoming a standard lever.
For buildersIf you run coding agents at scale, instrument cost per completed task and consider routing across models based on that metric.
