Axiom Math's agents formally verify the Stacks Project in Lean

First reported 2026-11-05

Axiom Math says its AI agents formally verified the Stacks Project, one of algebraic geometry's large reference libraries, in the Lean proof assistant. The company frames the work as a way to keep unchecked AI-generated proofs out of mathematics by relying on machine verification. The result is a notable demonstration that autonomous agents can produce large, checkable formalizations, though the candidates do not include independent review of the formal statements.

Why it mattersMachine-checked formalization at this scale shows a path to verifying AI-generated mathematical and software claims rather than relying on review.
For buildersLean-style verification is a model for checking agent output against formal specs, and it is worth studying as a pattern for high-stakes code.

Pros

  • Machine-checked proofs give strong guarantees about what is formally stated.
  • Scales verification beyond manual review.

Cons

  • A proof certifies only the formal statement, so a mismatch with intent remains possible.
  • Company-described outcome without independent expert validation in the candidates.

3/5 CODINGRESEARCH

Microsoft Research's PDD Kit adds formal verification to agent-written web apps

First reported 2026-11-05

Microsoft Research introduced PDD Kit, which turns a developer's intent into a formal spec and then proves that the code an agent writes satisfies it for every input, falling back to tests where proofs are not feasible. The authors argue that exhaustive line-by-line review does not scale as agents generate more code, and they demonstrate the approach on a full-stack web app. The approach aims to bring formal methods to everyday engineers rather than specialists.

Why it mattersSpecification-driven verification of agent output is one of the more practical answers to the review bottleneck created by AI coding.
For buildersWriting a precise spec as the contract for a coding agent may be a higher-leverage habit than reviewing generated code line by line.

Pros

  • Proofs can cover inputs that tests miss, and the spec becomes a reviewable contract.

Cons

  • Writing accurate formal specs requires skill, and a spec that misses intent still passes.
  • Scope beyond the demonstrated app is not established in the candidates.
microsoft.com
